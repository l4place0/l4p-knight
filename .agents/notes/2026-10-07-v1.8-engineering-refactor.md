# 任务归档 · v1.8：工程化改造

- **起点**：HANDOFF v1.7（功能收官后操作者要求工程化改造，「代码随处散落」）→ **产出**：v1.8
- **协作方式**：多 Agent 并行 × 文件所有权隔离——A(UI 拆分:main/index)·B(game 部件化:game/**)·
  C(测试整理:test/**)；**A/B 首轮撞子代理配额中断，次日补派续作完成**（A 实际在断点前已交付完毕，
  B 交付了 state/systems 两部件后中断，续作 Agent 审查前任产物无忠实性问题后完成剩余四部件 + facade）

## 架构决策（为什么这样改）

- **保持零构建 + file:// 双击可玩** → 禁用 ES modules/打包器；沿用「IIFE + ZERO_* 命名空间 +
  Node module.exports」双端模式
- **逻辑层**：js/game.js（1960 行）→ 54 行 facade + js/game/ 六部件（state/systems/player/enemies/
  bosses/rooms，各 265-396 行）；部件 = ZERO_GAME_PARTS 注册的工厂，createGame 按固定顺序装配；
  跨部件依赖一律经 ctx 显式传递（助手挂 ctx、循环方法挂 G），部件内零顶层即时逻辑 → 加载顺序安全
- **UI 层**：js/main.js（613 行）→ storage(89)/input(254)/hud(122)/ui(235) 四模块 + 155 行薄启动；
  跨模块依赖经 init(deps) 显式注入
- **测试层**：基建抽 test/lib.js（check/log/failureCount/simulateRun）；回归用例模块化
  （test/cases/ 导出用例数组，sim.test.js 一行挂载）；**新增 test/structure.check.js 结构守护**——
  index.html 脚本编排顺序钉死（含六部件先于门面、main.js 末位）/ 模块导出面 / 逐文件语法 / UI 模块存在性

## 遗留 / 注意事项

- **配额教训**：大批量并行 Agent 会撞子代理配额（本次 A/B 双双中断）；续派时让新 Agent
  先通读前任半成品并审查忠实性，比推倒重来省一半工作量
- structure.check 的顺序表是硬编码常量：**新增 js 文件必须同步改 index.html + 顺序表**（守护会精确打印分歧点）
- core.js 保持单文件（数据内聚，刻意不拆）；render/bot/audio/music 未动
- facade 对部件装配顺序敏感（state 最先、player 先于末尾 computeStats），顺序已在门面注释钉死
- 首轮并行的 A/B 中断产物曾让 structure.check 短暂红 4 项——C 组按「区分责任方、不越界修复」处理，
  该纪律有效
