# v1.12 三档整局难度

开始界面新增挑战、标准、休闲，默认标准，选择保存至本机。普通局、每日挑战、AI 演示及重试沿用选择；
HUD 和结算显示本局难度，每日排行以日期和难度分别记录。URL 支持 `?difficulty=challenge|standard|casual`。

用户指定口径为**整局通关率**。以下使用固定 M3 AI：commit=30、trackK=3、sight=100、delay=10、dashSkip=0.6。
四英雄等权，每批 25 个种子 × 4 英雄 = 100 局。从第一房正常输入推进七个普通房、四次商店和两个 Boss，
不跳关、不回满生命、不注入装备或提高玩家伤害。自动拾取、选晶片和购物是原 AI 行为。
普通局不使用每日修改器或本地元进度晶片；原型机在无头评测中可用。

| 档位 | 目标整局通过率 | 统一受伤倍率 | 标定批（seed 1–25） | 未参与调参的留出批（seed 51–75） | 留出批 95% Wilson 区间 |
| --- | ---: | ---: | ---: | ---: | --- |
| 挑战 | 37% | 0.265 | 40/100 | 36/100 | 27.27–45.76% |
| 标准（默认） | 67% | 0.2035 | 69/100 | 68/100 | 58.34–76.33% |
| 休闲 | 99% | 0.12 | 100/100 | 98/100 | 93.00–99.45% |

六批合计 600 局，超时、停滞、异常、越界/嵌墙/NaN 故障均为 **0**。seed 26–50 用于探索和调参，
不作为最终独立留出数据。留出批三个实测值均距目标 1 个百分点，目标均位于置信区间中。
标定验收允许 ±5 个百分点；留出验收要求目标位于 95% 区间，运行故障始终硬失败。
600 局包括标定集，不能合并后声称都是独立泛化结果。

完整逐局数据在同目录的 `difficulty-v1.12-{challenge,standard,casual}-{calibration,holdout}.json`，
包含实际参数、种子、英雄、结局、时长、所在区域、击杀/受击和双 Boss 击破数。
不同英雄在同档的通过率仍有差异，逐英雄结果在每份 JSON 的 `summary.perHero` 中；
这里的目标是四英雄等权汇总，不能当作每英雄或人类玩家的通关概率。
AI 演示使用现有默认 bot，其能力高于固定 M3 标尺，演示通过率不等于上述标定结果。

## 实现与故障修正

`core.DIFFICULTIES` 定义三档，统一 `damagePlayer` 入口在护盾吸收与不灭战意判断前缩放伤害。
弹幕、狙击/激光、接触、自爆、地雷和引力井共享该入口。敌人血量、速度、攻击节奏和地图保持原数据，
通过增加承伤容错降低难度，不使用无敌或根据种子强行指定输赢。
测试专用 `G.damageTuning` 可覆盖倍率，最终留出运行没有使用该覆盖。

整局验收暴露了两类寻路故障：清场时战斗方向承诺与补给吸引阻碍走向传送门；
电磁炮英雄长时间隔墙追盾卫时路点被移动承诺反复越过。
清场导航不使用战斗承诺；隔墙且十二秒无伤害进展时逐路点跟随，恢复视线即恢复承诺。
感知范围、危险延迟、可追踪弹数和冲刺放弃概率保留 M3 参数。修正后重新标定全部最终报告。
原问题门布局在十秒内正常交互进入第四区，prototype seed=33 整局回归可通关。

每局硬上限 1200 游戏秒，60 秒无战斗/房间/状态进展标为停滞，实际异常或空间不变量失败立即结束并报错。
超时和停滞不作为普通阵亡参与达标判断。

## 复现与验证

```powershell
npm start
npm run test:difficulty
node test/difficulty-balance.js --difficulty challenge --verify
node test/difficulty-balance.js --difficulty standard --verify
node test/difficulty-balance.js --difficulty casual --verify
# 留出数据：三档分别运行，使用未参与调参的种子：
node test/difficulty-balance.js --difficulty standard --seed-start 51 --holdout --verify
# 已安装 Playwright 和 Edge 时（可用 PLAYWRIGHT_MODULE 指定模块）：
node test/difficulty-browser.js
npm test
npm run test:mechanics-mutation
```

结构、12 组机制契约、44/44 变异检出、原小怪真实伤害契约、完整流程自检、动画及难度浏览器检查均通过。
历史单房与 Boss 标定工具显式使用原伤害倍率 1，保留旧报告口径；当前难度验收使用整局工具，
v1.10/v1.11 的“每房 <37%”不再是玩家默认档位要求。
