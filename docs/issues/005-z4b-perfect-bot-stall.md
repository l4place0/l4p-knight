# 005 · z4b：完美 bot 的战斗停滞

- 优先级：未评定（历史 issue）。
- 状态：closed（2026-10-09，v1.14.2 复现、修复与验收完成）。
- 修复提交：`f4d71cc`。
- 原记录：`docs/issue/z4b-perfect-bot-stall.md`；2026-10-09 统一迁入 `docs/issues/`，迁移时未复测；后续修复与验证见末尾。
- 来源：小怪标定之外的诊断发现。
- 版本：v1.10 工作区，基于 `458bd1a`。
- 场景：`z4b/prototype/s21`，矩阵默认完美 bot、区域期望构筑、当前小怪难度。

## 复现

```powershell
node test/matrix.js --seeds 21 --run z4b/prototype/s21
```

实测在约 55 游戏秒被矩阵判为停滞（20 秒无战斗进展）。玩家 HP=5、击杀=12，
最后一只炮台 HP≈91；最近快照玩家 `(370.6,193.6)`、炮台 `(457.9,118.0)`。
双方仍在移动，具体是地形、射线、武器或导航交互尚未定位，不直接归因于已登记的传送门问题。

`node test/enemy-balance.js --room z4b --perfect` 的 100 场景诊断也出现停滞，
该工具与矩阵的开局生命/护盾、停滞时限不同，统计不能混用。

## 处理方向

对最后一只敌人的视线、路径、开火条件、血量变化和卡死看门狗进行观测。
修复后保留该场景回归，确认不会借修改 bot 战斗能力改变已经固定的 M3 难度标尺。

本次接受的 M3 两批 1400 场景没有停滞，此问题保留为独立待办。

## v1.14.2 修复与验收（2026-10-09）

旧三种子当前能清房；扩大复测后发现 prototype/46 与 prototype/52 仍分别触发 20 秒无战斗进展停滞。

- seed=46：电磁炮在墙边短暂失去视线，反复释放开火输入，0.3 秒蓄力不断被取消。
  已有四秒零进展脱困阶段保持电磁炮开火输入，真实冷却与墙体射线保持；最终 **39.18 秒**清房。
- seed=52：AI 躲避墙后无法到达的冲锋预警，规避力反复打断 BFS 绕墙。
  仅在上述脱困阶段过滤隔墙冲锋预警，普通感知保持；最终 **31.28 秒**清房。

此处耗时为 Node 固定回归；浏览器分别 **28.47 秒 / 25.22 秒**清房，截图见 [完整报告](../qa/navigation-issues-v1.14.2.md)。
固定回归覆盖 prototype/21、stalker/9、prototype/43、prototype/46、prototype/52；分别移除两项修复，会重现对应停滞。
没有放宽原 20 秒判停滞门槛，也没有改英雄、小怪、首领、武器或难度数值。
