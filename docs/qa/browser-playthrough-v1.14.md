## 确认的问题

### P1：小地图与 HUD 遮住玩家和推进目标

第二区第二层战斗 1 清场后，角色位于右上角小地图覆盖区域，整个人物与武器不可见；手动 S 向下移动后，在地图下方重新出现。手动第一房间和守卫战也遇到左上角 HUD 遮住角色。第二区出口现场还能看到左上角 HUD 覆盖传送门。

来源：`js/render.js:265` 的小地图在世界绘制完后覆盖固定矩形；`index.html:44` 的左上 HUD 叠加在可行走区域。地图、出生与传送门选择没有避开这些覆盖区域。

修复目标：战斗 UI 不应让角色、敌人、门或传送门完全消失；应调整布局或在覆盖关键实体时让 UI 避让/淡出，并在浏览器实际重验。

以下截图中角色实际还在房间内，但被右上角小地图盖住；随后手动向下移动验证了遮挡原因。

![清场后的角色被小地图完全遮住](playthrough-v1.14/hidden-player.jpg)

### P2：狙击预警线穿墙，和实际射击的遮挡规则不一致

第四区第二层战斗 2 现场，狙击手从左下方瞄准，红线穿过中间右侧竖墙，终点仍画到玩家附近。实际攻击用墙体射线截断，视觉给出了错误的掩体信息。

来源：`js/render.js:425` 直接画 `l.x1/l.y1`；`js/game/enemies.js:225` 以后持续跟踪瞄准目标，但实际开火在 241–244 行调用 `G.raycastWall`。应保留跟踪/锁定逻辑，只让可见预警终点使用相同墙体裁剪。

![红色狙击预警线穿过右侧竖墙](playthrough-v1.14/sniper-warning.jpg)

另外，最终首领蓄力预告也存在相同渲染风险：`js/render.js:466` 的 `G0ray` 只判断屏幕边界，未查墙体。这一项有现场预告画面和源码依据，需修复时单独核对各条射线，而不是推断实际伤害穿墙。

### P2：房门表现未完成，封锁状态容易被看成错误占位

各房间仍是完整封闭的旧竞技场地图；所谓门是在边缘可达地面画一个框，战斗时中央画红叉，清场后换成箭头。没有门洞、通道或门板，因此用户截图中的红叉看起来像错误标记，空间连接也难以理解。

来源：`js/game/rooms.js:103` 在既有可达地面选择交互点；`js/render.js:251` 只画框与字符。此次手动进门、清场解锁及宝箱支路证明交互能运行；问题是房门的空间表达与状态反馈。

修复目标：完善门与墙的视觉衔接，明确显示战斗封锁/已开启，并同步验证碰撞、双向返回及玩家出生位置。
