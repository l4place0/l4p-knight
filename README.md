## 评测过程与结果（最终评定：A · 2026-10-05）

### 评测方式

1. **无头仿真验收（核心）**：`node test/sim.test.js` 在 Node 中以真实物理与碰撞逻辑运行游戏本体（零 mock），
   由内置 AI 代打系统从第 1 区一路打到击败最终 Boss，逐帧断言四项硬性标准（见下文自检清单）。
2. **浏览器实测**：本地服务器 + 页面截图逐屏核验（标题/英雄选择/战斗/Boss 三阶段/晶片与商店界面/胜利结算），
   并通过页面内无头推进钩子做长时回归，检查控制台零报错。
3. **真人试玩反馈闭环**：实测中发现的 AI 隔墙卡死问题，经诊断脚本定位后以 BFS 寻路修复，
   并将该场景固化为回归测试（【隔墙回归】）防止回退。

### 评测过程中发现并修复的关键缺陷

| # | 缺陷 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 晶片选择反复触发，游戏卡死在 `chip` 状态 | 房间肃清标志未置位，条件可重复满足 | 增加 `chipOffered` 一次性标志 |
| 2 | Boss 血量归零后永远不出 VICTORY | `killEnemy` 将 Boss 移出实体列表，死亡演出状态机失联 | Boss 改为独立"滞场死亡流程"（dying 状态机走完再结算） |
| 3 | 敌人刷进封闭凹室形成死局 | 地图存在全封闭内室 | 刷怪点改为"玩家出生瓦片 BFS 可达点"，地图无关化解决 |
| 4 | 狙击手被挤压嵌入墙体 9.7px | 逐轴钳位公式在箱体骑跨墙面时选错面 | 移动解析改为逐轴回退式（单帧位移 < 9px < 墙厚 16px，杜绝隧穿）+ 最小面推出解析 |
| 5 | 传送门可能生成在墙内导致无法进入 | 无候选点时直接放在"玩家上方一格" | 传送门只落在 BFS 可达瓦片 |
| 6 | **AI 隔墙锁定目标原地卡死（真人试玩发现）** | 目标选择不看视线 + 距离带逻辑在隔墙时既不压近也不开火，直线压近又与墙探避相互拉扯形成局部极小 | 目标选择偏好有视线者 + 无视线时 BFS 网格寻路绕行接敌；传送门导航同走寻路 |
| 7 | Boss 战期间 HUD 每帧抛错、结算界面无法弹出 | `bossPhases` 误用 `getElementById`（拿到单元素而非集合） | 改为 `querySelectorAll` 集合（无头仿真不跑 HUD，此缺陷只有浏览器实测能暴露） |
| 8 | 补给站遮罩不显示 | `showShop()` 未给遮罩添加 `.show` 类 | 补上类切换 |

## 运行方式

**直接游玩**：双击打开 `index.html` 即可（无任何外部依赖，file:// 协议可用）。
或启动本地服务器：

```bash
node test/serve.js 8941     # 然后浏览器访问 http://127.0.0.1:8941/
```

**运行硬性验收自检**（全自动无头仿真，Node ≥ 16，零依赖）：

```bash
node test/sim.test.js       # 退出码 0 = 全部通过
```

**场景矩阵**（测试漏斗上游 · 无头批量 × worker 并行 × 游戏时间断言）：

```bash
node test/matrix.js --seeds 1-3 --workers 6   # 地图×英雄×种子×合成构筑 全组合批量（秒级跑完）
node test/matrix.js --run z4b/stalker         # 单场景复跑
node test/matrix.js --seeds 1-5 --baseline test/matrix.baseline.json   # 与基线对比劣化
```

失败场景自动分类（超时/停滞/阵亡/越界嵌墙NaN/异常）并倾倒最近 32 游戏秒实体轨迹，
附 `replayUrl`（URL 即场景编码，浏览器打开即定向回放，可截图观测）。

- **三阶段区域守卫「零号 · 处刑者」**（第 3 区末尾）：
  - 阶段 Ⅰ · 弹幕压制 —— 旋转环形弹幕 + 瞄准扇形弹
  - 阶段 Ⅱ · 激光处刑 —— 五联扇形激光扫射（红光预警 → 白热光束）

- **三阶段最终首领「终焉 · 回响体」**（第 4 区末尾）：
  - 阶段 Ⅰ · 镜像裂变 —— 裂变镜像残影分身（场上限 5）+ 三连扇形弹
  - 阶段 Ⅱ · 引力陷阱 —— 引力井持续拉扯（冲刺挣脱、内爆收尾）+ 缓速环弹
  - 阶段 Ⅲ · 相位风暴 —— 相位跃迁 + 十字弹幕 / 全向环弹，兼发引力井与地雷

## ★ 核心硬性验收 —— 全自动仿真自检

`node test/sim.test.js` 在 Node 无头环境中以**真实物理与碰撞逻辑**运行游戏（不 mock 任何游戏代码），
由内置 AI 代打系统操纵玩家，从第 1 区一路打到击败最终 Boss。当前结果（v1.2 · 4 区域 / 双 Boss）：

```text
【通关仿真】seed = 1 / 2 / 3 → ✓ VICTORY（227.4s / 184.6s / 261.2s 游戏时间）
             双 Boss 阶段轨迹 1→2→3→1→2→3 · 转阶段血量精确落在 2/3 与 1/3 阈值
             补给站 4 次开启 · 金币经济生效 · 晶片/羁绊正常入手
【英雄仿真】磐石·重装员 / 夜隼·猎手 → ✓ 全英雄可通关（177.4s / 155.3s）
【压力仿真】30 敌 + 260 弹 × 600 帧 → 无异常，无卡死（单帧峰值 < 7ms）
【稳定性】7200 游戏秒连续快进 + 周期性高压脉冲 → 无异常
【隔墙回归】长墙完全阻隔目标，bot BFS 绕墙接敌（实测 5.6s 完成击杀）
【墙角回归】箱体角嵌入墙角，resolveOutOfWall 兜底分支当帧解除
```

**历史纪录**：通关次数 / 最高分 / 最高连击 / 最速通关自动存档（localStorage），标题界面展示。

覆盖四项硬性标准：

1. **主循环不卡死、无未捕获异常** —— 每帧 try/catch + 单帧 3 秒卡死熔断 + 长时快进压力脉冲。
2. **击退不穿墙、不越界** —— 逐帧断言所有实体不嵌墙（四角采样）、不出地图边界；
   机制上采用逐轴回退式移动解析（单帧位移 < 9px < 墙厚 16px，杜绝隧穿）+ 最小面推出解析。
3. **Boss 三阶段血量逻辑严密、无死锁** —— 断言转阶段血量阈值、阶段序列完整、
   Boss 死亡走独立滞场演出流程（避免状态机死锁），最终必定推进到 VICTORY。
4. **VICTORY 可触发** —— 三种子全部通关，结算界面（通关用时/击杀/最高连击/晶片构筑/评价）可交互重开。

## 设计说明（严防"简陋白块"）

- 所有角色/武器/敌军/Boss 均为手工绘制的字符画像素点阵（多层灰阶 + 高光 + 霓虹点缀），预渲染并缓存，
  受击时叠加白色剪影闪白；弹幕带径向发光贴图与拖尾；地面/墙体程序化杂点与每区域主题色。
- 黑白灰为主基调，霓虹青（己方/护盾）、血红（敌方/激光）、琥珀金（地雷/暴击/羁绊）三色仅作焦点与反馈。
