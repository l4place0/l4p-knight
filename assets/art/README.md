# 零号协议 · ImageGen 美术重绘

2026-10-08 使用内置 `image_gen` 绘图工具生成，所有生产图片随仓库本地打包。
完整实际提示词及透明选项保存在 [prompts.json](prompts.json)。
运行 `npm start` 后打开 [素材总览](http://127.0.0.1:8941/assets/art/preview.html)。

## 交付范围

| 文件 | 布局 | 内容 |
| --- | --- | --- |
| characters.png | 4 列 × 4 行，透明 | 四英雄、七小怪、双 Boss、传送门、地雷、残影 |
| items.png | 4 列 × 4 行，透明 | 六武器、补给箱、医疗心、电池、金币、六类弹体/战斗特效 |
| tiles.png | 4 列 × 4 行，不透明 | 每区一行；地板、地板变体、墙顶、墙面 |
| chips.png | 5 列 × 4 行，透明 | core.CHIPS 顺序的 19 个晶片，最后一格为攻击强化剂 |
| title.png | 横向，不透明 | 工业反应堆标题场景，中央保留暗色菜单空间 |

合计 69 格素材/背景。角色、物品、晶片顺序由 `js/render.js` 的图集映射定义；
格子尺寸按实际 PNG 宽高计算，不要求生成器输出固定像素尺寸。
运行时 Canvas 提取单格透明边界，并缩放到游戏逻辑尺寸，保留原 PNG alpha。
英雄最长边 20、普通敌人 20、Boss 36、武器 16、晶片 24、瓦片 16 像素。
受击闪白从实际图片轮廓生成；四英雄在选择卡与对局中各用独立外观。

弹幕拖尾、激光、预警圈、引力井、护盾、血条和文字仍由 Canvas 动态绘制，
使攻击范围、方向、时序和原战斗规则保持一致。图片加载失败时使用原代码像素画。
本次保留 v1.11 的数值、地图碰撞、生成规则与音效。

## 验证与复现

```powershell
npm start
# 另一个终端，需本地可用 Playwright 与 Edge：
# 若 Playwright 未装在本项目，可用 PLAYWRIGHT_MODULE 指向已安装模块路径。
node test/art-assets.js http://127.0.0.1:8941 msedge
node test/structure.check.js
npm run test:mechanics
npm test
```

浏览器验收检查五 PNG 解码、52 个精灵的透明边界/非空内容/闪白轮廓、
四英雄外观区别、四区与双 Boss 渲染、晶片/商店图标及阻断 PNG 请求后的回退。
截图输出到被 git 忽略的 `test/art-preview/`。总览页可独立查看并链接回游戏。

提示词中的像素尺寸属于生成目标；原图为高分辨率像素插画，游戏显示尺寸
由渲染层明确控制。浏览器需通过 HTTP 服务打开，保证透明边界读取同源。
